# MyBBForums MyBB plugin

Install `mybbforums.php` into `inc/plugins/`, `plugin/mybbforums/inc/plugins/lib.php` into `inc/plugins/mybbforums/lib.php`, `plugin/mybbforums/inc/tasks/mybbforums.php` into `inc/tasks/mybbforums.php`, and the Admin CP module into `admin/modules/config/mybbforums.php`, and the verification file `mybbforums-verify.php` at the forum's MyBB base path. Configure the service URL in Admin CP under Configuration → MyBBForums. The plugin supports MyBB 1.8.38+ within the 1.8 series and PHP 8.1–8.4 with Sodium and cURL; Admin CP management, service synchronization, and metric submission fail closed with a clear error outside that runtime range. The complete automated project suite has been exercised on PHP 8.1, 8.2, 8.3, and 8.4. A disposable live MyBB 1.8.39 installation on PHP 8.4/MariaDB 10.11.6 passed plugin activation, configuration-page rendering, task toggling, and aggregate metric collection against native MyBB tables. The MyBB 1.8.39 metric collector also passes against both MariaDB 10.11.6 and MySQL 5.7.44; other MyBB versions remain unverified. Activity collection requires per-statement timeout support: MySQL 5.7.8+ or MariaDB 10.3+. Unsupported metric databases fail closed and report metrics unavailable.

The verification endpoint is read-only: it signs a short-lived challenge with the installation Ed25519 key and returns no listing data. When the configured MyBB URL changes, the plugin asks the service to verify that same key at the new HTTPS origin; the service changes the listing URL only after proof succeeds. Categories and tags are loaded from the service's versioned taxonomy endpoints and shown as multi-select controls in Admin CP; selection limits and current service values are checked again when saved. If the service is unavailable, taxonomy controls fail closed while local profile drafts remain editable. Keep the private plugin settings/key directory available during a domain or server move. The plugin stores private settings, keys and queued aggregate samples in `../.mybbforums-private/` (outside the MyBB document root) with restrictive file permissions. Override with `MYBBFORUMS_DATA_DIR` only to another private location. The Admin CP lets owners rotate or revoke credentials, and successful deletion clears credentials and queued measurements locally. Plugin uninstall best-effort unpublishes and revokes the installation, then removes local credentials and queued aggregates even if the service cannot be reached. Reinstall creates a new installation identity and must use the service recovery flow; a forum URL alone cannot reclaim the listing. Deactivation disables the scheduled sync task. Service URL must be HTTPS in production.

Before its first service operation in each PHP request, the plugin checks `/version` and requires API v1, request-signature protocol v1, and installation-proof protocol v1. It sends `X-MyBBForums-API-Version: 1` with service API requests. If the service requires a newer or incompatible protocol, the plugin stops and shows an actionable update error rather than sending claims or listing changes.

Schedule `php bin/maintenance.php` at least every five minutes on the service host to purge deleted listing data on time and expire operational records. Restrict this command to the service operator account.

To run the optional integration check against an installed MyBB 1.8 tree without booting its forum or database, set `MYBB_CORE_ROOT=/path/to/mybb` and run `php website/tests/mybb-plugin-system.php` from the project root. This validates menu, action-module, and permission hook registration using MyBB's own `pluginSystem` class; it is a source integration check, not a full Admin CP/database installation test.

To run the live, read-only metric check against a disposable configured MyBB install, set `MYBB_METRICS_ROOT=/path/to/disposable-mybb` and run `php website/tests/mybb-metrics-live.php` from the project root. It connects using MyBB's configured `mysqli` or `mysql_pdo` driver and runs only the plugin's bounded aggregate queries; it does not insert test rows. If the database uses a non-default local socket, pass its path with PHP's `mysqli.default_socket` setting. The full `composer test` command skips this check unless `MYBB_METRICS_ROOT` is set.
